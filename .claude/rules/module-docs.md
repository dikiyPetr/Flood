# Документация модулей

Каждый модуль в `Assets/Modules/<Module>/` имеет собственный `CLAUDE.md` — индекс публичной поверхности и контрактов. Это первое, что читает Claude при работе с модулем.

## Когда обновлять `CLAUDE.md` модуля

Обнови файл `Assets/Modules/<Module>/CLAUDE.md` **в том же изменении**, если ты:

- Добавил, удалил или переименовал публичный тип (`public class`/`struct`/`interface`/`enum`).
- Добавил, удалил или переименовал публичный метод/свойство/событие у существующего публичного типа.
- Изменил `references` в `<Module>.asmdef` (новая зависимость / удалённая).
- Изменил инвариант или контракт, описанный в разделе «Контракты» CLAUDE.md.
- Переместил ключевой файл между поддиректориями модуля.

## Когда обновлять корневой `Assets/CLAUDE.md`

`Assets/CLAUDE.md` — корневой индекс папок и модулей. Обнови **в том же изменении**, если ты:

- Добавил, удалил или переименовал модуль (новый/удалённый `Assets/Modules/<Module>/<Module>.asmdef`) — обновить таблицу «Модули».
- Переписал секцию `## Назначение` в `<Module>/CLAUDE.md` так, что роль модуля изменилась — обновить ячейку «Назначение» в таблице.
- Изменил `references` в `<Module>.asmdef` — обновить колонку «asmdef refs». Этот триггер пересекается с per-module правилом выше: один и тот же коммит правит и модульный `CLAUDE.md`, и корневой индекс.
- Добавил, удалил или перепрофилировал верхнеуровневую папку под `Assets/` (например, появилась `Audio/`, удалили `Configs/`) — обновить таблицу «Папки».

Корневой файл — только индекс. Контракты, типы и точки расширения — в `<Module>/CLAUDE.md`, не дублировать.

## Что НЕ требует обновления

- Правка тела приватных методов.
- Рефакторинг внутри публичного метода без изменения сигнатуры/контракта.
- Изменения публичного API внутри модуля без сдвига его роли — корневой `Assets/CLAUDE.md` не трогать (только модульный).
- Изменения тестов.
- Косметика (using-сортировка, форматирование).

## Стиль `CLAUDE.md` модуля

Структура (фиксированная, не вариативная):

```
# <Module>

## Назначение
1–2 строки: что делает модуль и зачем.

## Зависимости (asmdef)
Список references с короткой причиной для каждой.

## Ключевые типы
Таблица или список: имя — путь — роль (1 строка).

## Контракты
Инварианты, порядок вызовов, ограничения, которые не видны из сигнатур.

## Точки расширения
Где в файле/методе вставлять следующие фичи из GDD.
```

Не дублируй GDD — ссылайся на разделы (`§3.1`, `§3.6` и т.п.). Не описывай внутренние реализации (тело методов) — только публичный API и контракты.
