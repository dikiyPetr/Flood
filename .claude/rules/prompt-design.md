# Правила написания системных промтов

## Именование
- Скиллы: `skills/c-{name}/SKILL.md` — чтобы все проектные скиллы находились по `/c-`
- Файлы правил: `rules/{тема}.md` — kebab-case тема

## Структура
- Корневой `CLAUDE.md` — пустой. См. `rules/root-claude-md.md`.
- Правила — в `rules/*.md` с `paths:` frontmatter. Авто-подгрузка по scope, не через `@` из корня.
- Скиллы — в `skills/c-{name}/SKILL.md`. Триггеры в description; могут `@`-импортить rules для своего сценария.
- Модульные правила — в `<dir>/CLAUDE.md` (auto-load в поддереве).
- Один промт — одна ответственность.

## Написание промтов
- Заголовки `##`, вложенность не глубже 2 уровней
- Запреты — явно: "НЕ делать X", "не трогать Y"
- Scope-ограничения агентов — таблицей (что делать / не делать)
- Повторяющиеся паттерны (ORIGINAL_TASK, PREVIOUS_WORK) — не объяснять, просто использовать
- Не писать очевидное из контекста задачи
- ВСЕГДА используй Frontmatter, если их можно использовать
- `<!-- ... -->` — заметки для пользователя (ссылки на скрипты, пояснения); агентом не воспринимаются как инструкция

## Что не писать
- Объяснения очевидного поведения
- Одно правило в нескольких местах
- Анти-паттерн, дублирующий уже сформулированное позитивное правило
- Секцию в 1–2 строки под отдельным заголовком — слить с соседней по смыслу
- Boilerplate-синтаксис (точный шаблон атрибута, дефолтная форма поля); вместо шаблона — «обязателен `X`»
