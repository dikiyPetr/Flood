# Масштабировать карту до 100×100 и оптимизировать grid до 500

## Что

Поднять размер мира с 20×20 до **100×100 world units** и разрешение сетки территории с 64×64 до **500×500** (целевое; 256×256 — минимум приёмки). Чтобы это работало стабильно на 60 FPS, переписать узкие места на GPU compute. Камера — adaptive zoom-out.

Дизайн-параметры зафиксированы в:
- [Documents/GDD/meta/perf-budget.md](../GDD/meta/perf-budget.md) — потолки и стратегия оптимизации.
- [Documents/GDD/systems/arena.md](../GDD/systems/arena.md) — целевые размеры мира/сетки/базы.
- [Documents/GDD/systems/enemies.md](../GDD/systems/enemies.md) — потолок ≤200 врагов остаётся.
- [Documents/GDD/pillars.md](../GDD/pillars.md) — pillar 5 «адаптивный одноэкранный обзор».

Работа выполняется в worktree `unity` (`D:\projects\Flood-worktrees\unity`, `feat/unity`). Этот файл — постановка из worktree `gdd`.

## Зачем

Текущая 20×20 карта не даёт места для геймплейной плотности — крупные петли, дальние шахты, мульти-секторные волны не помещаются. Без оптимизации grid-up скейл невозможен: `ResolveClosure` (CPU O(N²) full-grid scan) и `FlowFieldBuilder` (CPU Dijkstra O(N² log N)) при grid=256+ становятся источником stutter'а на каждом замыкании и ребилде flow-field.

## Готово, когда

Все пункты должны быть подтверждены тестом (профайлер + плейтест-сессия).

### Размер карты и сетки

- [ ] World mesh (`Plane` в `Assets/Scenes/New Scene.unity`) масштабирован до scale `{10, 1, 10}` (100×100 world units).
- [ ] Edge-коллайдеры по периметру обновлены под новый размер.
- [ ] `ArenaConfig.GridResolution` поднят до 500 (или до фактически достижимого потолка ≥256, см. ниже).
- [ ] `TexelsPerWorldUnit` зафиксирован (2.56 или 5.12 — выбор задокументирован в `meta/perf-budget.md`).

### GPU pipeline (Q1.4 + Q3.2)

- [ ] `EnclosedRegionFinder` / `ArenaState.ResolveClosure` переписаны на compute-shader (BFS по grid-маске). Stutter на замыкании = 0 фреймов.
- [ ] `FloodFillAnimator` переведён на GPU compute (параллельная волна по фронту, ping-pong RT). `FillTickInterval` сохраняется как gating расхода краски.
- [ ] `FlowFieldNavigator` использует GPU jump-flooding вместо CPU Dijkstra (см. `Assets/Modules/Navigation/CLAUDE.md`).

### Камера (Q1.3)

- [ ] Camera имеет adaptive zoom-out: статична при маленькой активной петле, отъезжает при крупной. Точная функция zoom — открыта (TODO в [pillars](../GDD/pillars.md)), реализуется по простейшему варианту с возможностью тюнинга.

### Контент на новой карте

- [ ] База в сцене расширена до радиуса 4–6 ед. (одна центральная, без филиалов).
- [ ] 12 предопределённых точек ресурсов перераспределены по 100×100 карте вручную в сцене. 2 шахты краски + 1 шахта масла — расставлены префабами.
- [ ] `WaveDirector` (если делается в той же задаче — иначе следом) умеет разнести спавн до 6 секторов на волне 5. Если `WaveDirector` ещё не реализован — не блокирует scale-up; debug-спавнеры адаптируются под новый периметр.

### Перформанс-приёмка (Q1.2 + Q3.1)

- [ ] Standalone PC-билд, профайлер: **60 FPS стабильно** при ≤200 одновременных врагов и активном замыкании.
- [ ] Минимум 45 FPS на пиковых событиях (волна 5 + замыкание + пиковая толпа).
- [ ] RT-память на маски пола суммарно ≤ 8 МБ.

### Документация

- [ ] `Documents/GDD/meta/perf-budget.md` обновлён фактическими цифрами после реализации: реальный TexelsPerWorldUnit, найденный потолок grid (если не 500), измеренные FPS.
- [ ] Если grid=500 не дотянул до 60 FPS — узкое место и safe-разрешение задокументированы в perf-budget.md.
- [ ] Соответствующие модульные `Assets/Modules/*/CLAUDE.md` (Floor, Navigation, Enemy) обновлены под новые цифры.
