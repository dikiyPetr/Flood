# Todo

Список задач разработки. Один файл на задачу. Простой формат: kebab-case-имя, frontmatter со статусом, тело — описание + критерии «готово» + лог прогресса.

Для сводных тикетов в issue-трекере, roadmap и долгоживущих эпиков это **не** место. Здесь — конкретные действия, которые кто-то выполняет.

## Структура

- Файлы лежат плоско: `Documents/Todo/<slug>.md`. Без подпапок по статусам.
- Имя файла = `id` во frontmatter.
- Сортировка — алфавитная по имени; если важен порядок, добавь префикс `01-`, `02-` (но обычно не нужно).

## Frontmatter

```yaml
---
id: <slug>           # стабильный, == имя файла без .md
title: <человекочитаемый рус.>
status: pending|in-progress|done|blocked
created: YYYY-MM-DD
updated: YYYY-MM-DD  # дата последнего изменения статуса/прогресса
---
```

### Семантика `status`

| Значение | Когда |
|---|---|
| `pending` | задача поставлена, к ней никто не приступал |
| `in-progress` | кто-то в работе |
| `blocked` | работа начата, но застряла на внешнем — в теле обязательно описать **что блокирует** и **что разблокирует** |
| `done` | сделано; файл остаётся в `Todo/` ещё 1–2 спринта для истории, потом архивируется или удаляется |

## Тело задачи

Минимальная структура:

```markdown
# <Заголовок>

## Что

1–3 строки: что именно сделать.

## Зачем

1–2 строки: какую проблему решает, какой результат.

## Готово, когда

Чеклист критериев приёмки. Без галочек = задача не закрыта.

- [ ] критерий 1
- [ ] критерий 2

## Прогресс

Лог в обратном хронологическом порядке. Одна запись = одна дата.

- **YYYY-MM-DD** — что сделано / какое решение принято / на чём застряло.
```

## Когда обновлять

- Старт работы → `status: in-progress`, `updated: <today>`, запись в «Прогресс».
- Каждое значимое продвижение → запись в «Прогресс», `updated: <today>`.
- Блокер → `status: blocked`, описать в теле что блокирует.
- Финал → `status: done`, отметить чеклист, `updated: <today>`.

## Связи с другими директориями

- Задачи могут ссылаться на `Documents/GDD/systems/<id>.md` (откуда взялась идея) и на `Assets/Modules/<X>/CLAUDE.md` (где менять).
- Обратные ссылки из GDD/CLAUDE.md в Todo не требуются — задачи короткоживущие, GDD не должен на них опираться.

## Запреты

- Не плодить статус-папки (`pending/`, `done/`) — frontmatter достаточно.
- Не использовать `[ ]`/`[x]`-чеклисты вместо `status:` — они для критериев приёмки внутри тела, не для статуса задачи.
- Не дублировать GDD-семантику маркеров (`> SoT:`, `> DISPUTED:`) — это инструменты GDD, не Todo.
